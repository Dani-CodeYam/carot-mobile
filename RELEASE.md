# Shipping El Carot to the App Store

Everything between a working checkout and a Pre-Order listing. Written for the
person who owns the Apple Developer account — most of the work is in App Store
Connect, not in this repo.

`MOBILE_SETUP.md` covers day-to-day device builds. This file covers release.

## What the app is, for the paperwork

El Carot has **no backend**. Draws, the question you type, the history, and the
signed-in session all live in AsyncStorage on the device. Nothing is
transmitted anywhere. That single fact answers most of App Store Connect's
questionnaire, so keep it in mind while filling forms out.

## Prerequisites

| | |
| --- | --- |
| Apple Developer Program | Paid membership, **active** |
| Xcode | **26.0 or later** — since 28 Apr 2026 Apple only accepts builds made with the iOS 26 SDK |
| Bundle ID | `com.elcarot.mobile`, registered under your team |
| App icon | `assets/icon.png`, 1024×1024, opaque, **square corners** — Apple rounds them itself and rejects pre-rounded art |

Check your toolchain:

```bash
xcodebuild -version          # must be 26.x
xcodebuild -showsdks | grep iphoneos
```

Then check that Xcode is signed in with the Apple ID that actually holds the
membership. Open **Xcode → Settings → Accounts**: if the account shows only
"Personal Team", the paid membership is on a different Apple ID, or the
enrolment is not active. A free personal team cannot sign this app at all —
Sign in with Apple is a paid-only capability — and it cannot upload to the App
Store either. Confirm at
[developer.apple.com/account](https://developer.apple.com/account), which shows
your Team ID under Membership details.

## Before you submit — blockers first

- [ ] **Know the likeness risk.** The deck art builds on photographs of real,
      recognisable people. Guideline 5.2 covers intellectual property and
      publicity rights, and celebrity likenesses are a known rejection trigger.
      The icon deliberately avoids this — it is illustration, not a face — which
      matters because the icon is the most scrutinised asset you ship, appearing
      in search results and on the Pre-Order listing. In-app card art is judged
      far less harshly, so the exposure is real but modest. This is a judgement
      call, not a defect; just know it is the likeliest reason a submission
      comes back.
- [ ] **Resolve the Google sign-in button.** Without
      `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` the button renders disabled reading
      "not configured", and shipping a visibly dead control invites a
      rejection for incomplete functionality. Either configure Google fully
      (see `README.md`) or hide the option in native builds. Sign in with
      Apple works on its own and satisfies guideline 4.8.
- [ ] **Consider in-app account deletion.** Guideline 5.1.1(v) requires apps
      that support account creation to also offer deletion. El Carot creates
      no account on any server — sign-in only writes a local session — so the
      guideline arguably does not apply. Reviewers are literal about visible
      login buttons, though, and a "delete my data" action in *Tu cuenta* that
      clears the scoped keys removes the argument entirely. Cheap insurance.
- [ ] Bump `expo.version` in `app.json` for each public version, and
      `expo.ios.buildNumber` for **every** upload — App Store Connect rejects a
      build number it has already seen, even for a build that was never
      released.

## Build and install on your iPhone

See `MOBILE_SETUP.md` → *Building for a Real iOS Device* for the full walkthrough,
including how to set the signing team on the generated project. Short version:

```bash
npx expo prebuild --platform ios --clean
# set DEVELOPMENT_TEAM on the ElCarot target, then:
xcodebuild -workspace ios/ElCarot.xcworkspace -scheme ElCarot \
  -configuration Release -destination 'id=<UDID>' \
  -derivedDataPath ios/build -allowProvisioningUpdates build
```

`npx expo run:ios --device` does not pass `-allowProvisioningUpdates` and will
fail to create a profile on a fresh machine.

The first launch on a new device needs the profile trusted:
**Settings → General → VPN & Device Management** → your Apple ID → **Trust**.

`ios/` is gitignored and regenerated by `prebuild`, so never hand-edit it
expecting the change to survive.

## Archive and upload

No EAS required — Xcode does it.

1. `npx expo prebuild --platform ios --clean`
2. `open ios/ElCarot.xcworkspace`
3. Select **Any iOS Device (arm64)** as the destination (not a simulator, not
   your phone — archiving requires a generic device).
4. **Product → Archive**
5. In the Organizer that opens: **Distribute App → App Store Connect → Upload**
6. Let Xcode manage signing. It needs your Apple ID added under
   **Xcode → Settings → Accounts**.

Processing on Apple's side takes 10–60 minutes before the build appears under
your app's **TestFlight** and **Distribution** tabs.

Because `ios.config.usesNonExemptEncryption` is set to `false` in `app.json`,
the export-compliance question is answered in the Info.plist and Xcode will not
prompt for it on each upload.

## Screenshots

Required: at least one 6.9" screenshot, at **1320 × 2868** portrait. Maximum 10.
PNG or JPEG, **no alpha channel**. Other sizes are scaled from it automatically,
so one set is enough.

Take them from the Simulator, not from the web preview — the preview is
react-native-web and has no status bar, no safe-area insets, and can measure
fonts differently.

```bash
xcrun simctl boot "iPhone 17 Pro Max"       # a 6.9" device
npx expo run:ios --device "iPhone 17 Pro Max"
# Then, per screen:
xcrun simctl io booted screenshot ~/Desktop/carot-01.png
```

The captured codeyam scenarios are the guide for *which* states to show — they
are already the interesting ones. Good candidates, in order:

1. `Home` — the entry point, greeting and the three ways in
2. `Carta del día - Revelada` — the daily card face up with its meaning
3. `Tengo una pregunta específica` — the question flow
4. `Todas las cartas` — the gallery, which shows the deck off
5. `Cartas anteriores - Con historial` — the trail of past readings

## App Store Connect setup

Create the app record: **Apps → + → New App**. Platform iOS, the bundle ID
above, and an SKU (any private string — `carot-mobile` is fine).

### App Privacy

**Data Collection: No.** Nothing leaves the phone. Sign in with Apple returns a
name and email, but they are written to local storage and never transmitted to
a server you control, so there is no collection to declare. Answer the
questionnaire accordingly rather than over-declaring — an inaccurate privacy
label is itself a rejection reason.

### Age Rating

El Carot has no user-generated content, no ads, no purchases, and no web
browsing. Fortune-telling and horoscope content generally lands at 12+ — answer
the questionnaire honestly and let it compute the rating.

### Listing metadata

- **Name**, **subtitle**, **promotional text**, **description**, **keywords**
- **Support URL** and **Privacy Policy URL** — both mandatory. The privacy
  policy is required even though nothing is collected; a short page saying
  exactly that is sufficient and is the honest version.
- **Category** — Lifestyle or Entertainment
- **Copyright**, and App Review contact details

The app is bilingual (Spanish/English), so add both localizations to the
listing if you want it discoverable in either.

## Pre-Order

Verified against Apple's App Store Connect help, and worth reading twice
because parts of it are one-way.

**Pre-Order does not skip App Review.** The sequence is: publish the pre-order,
*then* submit the app for review, and only once it is approved do you release
it.

1. **Apps → El Carot → Pricing and Availability → Set Up Availability**
2. Choose **Publish as Pre-Order** → Next
3. Pick a release date — it must be **between 2 and 180 days** from now → Next
4. Pick countries/regions → Next → **Confirm**
5. Submit the app for review as normal
6. Once approved, click **Release This Version**

The listing goes live for pre-order immediately, though it can take up to 24
hours to appear for everyone. If the release date is under 180 days out, the
store shows the exact date; beyond that, only the month and year.

### What you can still change

Release date (before it passes), price, and the build itself — you can submit
new versions throughout the pre-order period. You can also release early.

### What you cannot undo

Once the release date passes in a region, the app is released there and **can
never be offered for pre-order again**. The same applies if you remove the
pre-order before the date: you cannot republish it as a pre-order. Decide the
date deliberately.

Paid apps: customers are not charged until release, and if you lower the price
in the meantime they pay the lower amount.

## After approval

- Use TestFlight for real-device testing before each submission — the build you
  archive is the build you test.
- Every new upload needs a fresh `ios.buildNumber`.
- App Review typically takes 24–48 hours, but leave slack ahead of a pre-order
  release date you have already announced.
